# CLAUDE.md — Working rules for this repository

InspirationOS: a private, single-user app that turns Adam's Instagram self-DM
export into reviewed, clustered inspiration items and AI-generated portfolio
projects. Full scope and constraints live in `docs/`.

## Before changing any code

1. Read `docs/IMPLEMENTATION_PLAN.md` and find the milestone you were asked to
   work on.
2. Read the docs relevant to your change **before** editing:
   - Product behavior/scope → `docs/PRODUCT_SPEC.md`
   - Services, jobs, parsing, enrichment, AI providers → `docs/ARCHITECTURE.md`
   - Any model/table/column → `docs/DATA_MODEL.md`
   - Auth, logging, deletion, uploads → `docs/PRIVACY_SECURITY.md`
   - Writing or changing tests → `docs/TESTING_STRATEGY.md`
   - Compose/CI/VPS → `docs/DEPLOYMENT_PLAN.md`

## Milestone discipline

- Work **only** on the milestone the user requested. Do not start the next
  milestone, and do not implement features from later milestones "while you're
  at it."
- The full personal-use scope (all 10 milestones) is required. Never remove or
  defer a requirement because it seems "not needed for an MVP" — the user has
  explicitly rejected MVP-trimming.
- A milestone is complete only when every acceptance criterion in
  `docs/IMPLEMENTATION_PLAN.md` passes. Tick its checkboxes as you go.
- **Stop after completing the requested milestone.** Summarize what was done,
  which tests pass, and any known limitations. Wait for the user before
  continuing.

## Privacy rules (non-negotiable)

- **Never commit** secrets, API keys, `.env` files, raw Instagram exports,
  private messages, uploaded files, or generated user data. All private data
  lives under gitignored paths (`var/`, `private-data/`, `uploads/`).
- **Never log private message bodies.** Fields that must never appear in logs,
  error messages, job payloads, or AI request records: `text`, `share_text`,
  `adjacent_text`, `context_note`, `content_md`, and anything derived from
  message content. Log IDs and counts instead.
- **Tests use synthetic fixtures only**, generated by
  `backend/tests/fixture_builder.py`. Never place real export data in tests,
  fixtures, or git — not even "just one real message."
- Never ask for the user's Instagram password, automate Instagram login, or
  bypass Instagram access controls. Import must work fully offline; enrichment
  network calls are consent-gated and per-item/batch only.
- Never invent what a reel is about. Items without real text (share text,
  adjacent text, enrichment result, or user note) stay `needs_context` and are
  excluded from AI generation input in code.

## After every modification

Run, and get green, before reporting done (from repo root; skip suites whose
code doesn't exist yet in the current milestone):

```bash
# Backend
cd backend && python -m ruff format . && python -m ruff check --fix .
cd backend && python -m mypy app
cd backend && python -m pytest -q

# Frontend
cd frontend && npm run lint && npx tsc --noEmit && npm run test -- --run

# E2E (requires the compose stack; runs in CI if Docker is unavailable locally)
cd e2e && npx playwright test
```

Integration tests that need Postgres/Redis skip automatically when the services
are unreachable; CI always runs them. Do not mark a milestone complete with
failing or silently-skipped acceptance tests — if Docker isn't available
locally, say so explicitly and verify via CI.

## Documentation upkeep

When a change alters architecture, schema, behavior, commands, or security
posture, update the matching doc(s) in `docs/` **in the same session**. The
docs are the source of truth for future sessions; stale docs are bugs.

## Environment notes

- Windows 11 host. Check for Docker Desktop availability before suggesting
  `docker compose` commands (it was not installed as of 2026-07-14; WSL2 is
  also absent). Use `python -m venv` + pip; `make` is not available locally —
  run the underlying commands directly.
- Git: default working branch is `master`; do not commit or push unless the
  user asks. Pre-commit hooks (ruff, gitleaks) must never be bypassed with
  `--no-verify`.
